■ 2026-11-17　导入：没有时刻列的 CSV 也能导入／一次选择多个文件
（修改前的版本 → _backup_1117）

【修改文件】CsvImport

1. 没有时刻列的 CSV 也能导入
   - 以前只认 TimeStamp / time_ms 列，没有就提示「時刻の列（TimeStamp）が見つかりません」并停止
   - 现在可识别的时刻列：TimeStamp・timestamps（Unix 秒）・t_ms（旧 demo 系统，Unix 毫秒）・time・time_s・datetime・time_ms 等
   - 完全没有时刻列时：弹出窗口询问每行的记录间隔（1 秒 / 0.5 秒 / 0.2 秒 / 0.1 秒 / 256 Hz），按等间隔处理；
     同一批文件只问一次。开始时刻取文件名中的日期，没有则取文件的修改时间
   - 这种文件开始时刻可能相同：已存在同名文件时自动加编号（例：…_2_mm.csv）
2. 一次选择多个文件导入
   - 使用 macOS 标准的文件选择窗口，按住 ⌘ 或 Shift 可以多选（只显示 .csv）
   - 依次处理，左侧显示进度（例：読み込み中（2 / 5）… 40%）
   - 只导入 1 个文件时，和以前一样完成后自动回放；多个文件时不回放，显示「○ 件をインポートしました」及失败的件数

【验证】
- 没有时刻列的 CSV（1200 行・0.1 秒间隔）→ 120 秒分；Unix 秒 timestamps 列的 CSV（600 行）→ 60 秒分
- 同一个无时刻列文件导入 2 次 → 第 2 次自动加编号


■ 2026-11-16（2）　光绘恢复 11/14 版的风格／Boids 的身体不再变成断开的点
（修改前的版本 → _backup_1116b）

【修改文件】LightPainting / Artwork / SwarmSim / BoidControl / SplitScreenView / Replay / Boid

1. 光绘恢复 11/14 版的算法（时间压缩 2000 步、个体数 20%）
   - 原因：用实时鱼群真实轨迹（几万步）累积时，同一条轨道被反复描几十遍，自动曝光后满屏都是亮线，过于强烈
   - 光绘与实时・回放的模拟分开：调整实时 Boids 的规则不会影响光绘
   - 风格编号 LP_STYLE_VERSION = 3。上一版生成的作品（风格 2）自动移到 artworks/_old_style2/，全部重新生成
   - 960 宽的结果与以前画廊缓存（*_w1600x1000_960.png）逐像素相同；作品为同一构图的 3840×2400
   - 回放仍然与当时的实时画面完全相同，结尾淡入作品（作品的线条不是回放中那群鱼的轨迹）
2. Boids 的身体：每走一步就画一次（以前是每帧画一次）
   - 原因：固定步长下，电脑忙时（例如后台在生成作品）一帧会补走 2～4 步，但只画最后一个位置，
     身体的圆点之间出现空隙，看起来像一串断开的点
   - 实时：一帧走了几步就画几次 → 圆点重叠成连续的身体（与以前的小蝌蚪一样）
   - 回放（倍速）：沿这一帧经过的位置画成连续的线

【验证】
- 以 20fps（每帧 3 步）运行：身体连续；回放倍速时为连续的线
- 回放 vs 实时：逐位相同（差异 0）
- 光绘 960 宽与 11/14 版的缓存：差异像素 0

■ 2026-11-14（2）　虚拟画布（任何显示器结果相同）・高解像度保存（3840×2400）
（修改前的版本 → _backup_1114b）

【修改文件】Boid / LightPainting / Replay / Gallery

1. 虚拟画布：光绘与回放的模拟改在固定的 1600×1000 空间中进行（LP_WORLD_W / LP_WORLD_H），
   与显示器分辨率无关。以前模拟直接在屏幕像素空间进行，Boids 的半径和速度是固定像素值，
   所以画面越大轨迹越不同；把文件夹拷到其他电脑时，画廊会显示旧电脑生成的缓存，与回放不一致。
2. 跨电脑的逐位一致：决定轨迹的 sin / cos 与色调映射的 exp 改用 StrictMath
   （Math 在 Intel / Apple Silicon 等 CPU 上最后一位可能不同，混沌系统会放大这种差异）。
3. 缓存文件名包含虚拟画布尺寸：eeg_session_xxx_w1600x1000_960.png（拷到任何电脑上都正确）。
4. 高解像度で保存：回放窗口标题栏的按钮，以 3840×2400 输出到 exports/ 文件夹（约 3 秒，后台进行）。
   与画廊・回放是同一模拟，只是分辨率更高：构图完全相同，线条粗细与辉光按分辨率等比放大。
5. 为支持 4K：模糊改为滑动窗口算法（与半径无关）；自动曝光的百分位改为抽样计算。
6. 光绘比例统一为 16:10（虚拟画布）。画廊、回放窗口、删除确认中的缩图都按此比例显示。

【验证】
- 3 种不同的窗口尺寸（1600×1000 / 1280×720 / 1700×1050）：960px 与 3840px 输出的文件逐字节相同
- 回放结尾 = 画廊图片 = 直接生成：差异像素 0；回放 2 次：差异 0
- 4K 输出缩小后与 960px 版本构图一致

【注意】
- 缓存文件名改变，首次打开画廊时所有光绘会重新生成一次（构图会与之前不同，此后在任何电脑上都固定）。
  旧的 *_full_600.png / *_full_960.png 不再使用，可以手动删除。
- 实时画面仍按屏幕尺寸运行（行为不变）；只有光绘与回放使用虚拟画布。


■ 2026-11-14　修复：回放结尾的光绘每次不同、与画廊中的光绘不一致
（修改前的版本 → _backup_1114）

【修改文件】Boid / LightPainting / Replay / Gallery

【原因】
1. 模拟中的随机数（初始位置・速度、每步的抖动、个体数调整时增删哪个个体）没有固定种子；
   Boids 是混沌系统，起点的微小差异会被放大，最终轨迹完全不同。
2. 画廊缩图（个体数比例 0.2・600px）与回放（0.4・960px）的参数不同。
3. 画廊图片在后台线程生成，实时画面与回放在主线程运行，三者共用同一个全局随机数，
   即使设定种子，消耗顺序也无法保证。

【修复】
- 每次光绘模拟使用自己的随机数生成器（java.util.Random），种子由 CSV 文件名决定
  （LightPainting.pde 的 lpSeedFor()）。同一会话 → 同一种子 → 同一张光绘；不同会话仍然不同。
- Boid 增加带随机数生成器的构造函数；实时画面仍使用原来的全局随机数（行为不变）。
- 画廊与回放使用完全相同的参数：个体数比例 0.2（画廊原有的值，保持原来的风格）、分辨率 960px。
- 辉光半径按分辨率自动缩放（以 600px 为基准），分辨率提高后观感不变。
- 回放的个体数比例由 0.4 改为 0.2（与画廊一致），回放中的个体会比以前稀疏一些。

【验证（逐像素比较）】
- 同一会话生成 2 次：差异像素 0
- 画廊图片（后台线程生成）与直接生成：差异 0
- 回放结尾的光绘与画廊图片：差异 0；回放 2 次：差异 0
- 不同种子：大部分像素不同（不同会话仍得到不同的图）

【注意】
- 缓存文件名包含分辨率（*_full_960.png），首次打开画廊时所有光绘会按新规则重新生成一次。
  旧的 *_full_600.png 不再使用，可以手动删除。
- 光绘与画面尺寸有关：在不同分辨率的显示器上运行会得到不同的图（同一显示器上始终一致）。

■ 2026-11-12　噪声处理・回放・Data Management
（修改前的版本 → _backup_1112）

【新增文件】
- NoiseFilter.pde　噪声判定（实时录制与 CSV 导入共用）
- Replay.pde　　　倍速回放 → 过渡为光绘
- DataManager.pde　Data Management 画面（文件列表）
- CsvImport.pde　　外部 CSV（Mind Monitor）导入
- Toast.pde　　　　画面上方的简短通知

【修改文件】
EmotionCalc / SessionIO / OscInput / Recording / LightPainting / Gallery /
SideMenu / MouseInput / KeyInput / Modified_SplitScreen / SplitScreenView

1. 噪声处理（NoiseFilter.pde）
   - 满足以下任一条件的样本视为噪声，不用于 A/V 计算，也不写入 CSV：
     · NaN / 无穷大
     · 频段值超出 [-2.0, 3.0]（log 尺度；实测正常值约 -0.6〜1.9，可排除 -9 之类的尖峰）
     · 接触不良：horseshoe / HSI 中有电极为 4（bad）
     · 冻结值：θ/α/β 中有电极的值与上一个样本完全相同（Mind Monitor 掉包时重复发送旧值）
     · （原有）咬牙前后 1.5 秒
   - A/V 为 ±1.0 本身不视为噪声（那是超过 ±2σ 后的截断，多数源于校准基准偏移）。
   - 录制中在按钮下方显示「ノイズ除去 N 秒（直近：原因）」；结束时在通知与控制台显示统计。
   - CSV 改为"每接受一个干净样本写一行"（以前是每秒写当前值，噪声期间也会写入旧值）。
   - 判定、计算、写入使用同一个快照（以前 OSC 线程可能在计算与写入之间更新数组，
     导致同一行的 A/V 与频段值不一致）。

2. 回放（Replay.pde）
   - 在画面中央的窗口中，用 CSV 的 A/V 倍速回放 Boids，同时累积轨迹的光；
     回放结束后，累积的光成像为光绘并淡入（结尾的光绘 = 本次回放全部轨迹的凝结）。
   - 触发：结束瞑想（按钮 / Space）后自动回放；画廊中点击光绘；Data Management 中双击或「▶ 再生」；导入完成后。
   - 关闭：右上角 ×、光绘显示完成后点击窗口、或 ESC（回放中 ESC 不会退出程序）。
   - 按 X 退出或按 R 重新校准时结束录制，不进行回放。
   - LightPainting.pde：lpSimStep 增加数量比例参数；辉光与曝光处理独立为 lpFinish()，画廊缩图与回放共用。

3. Data Management（菜单第 3 项）
   - 左侧栏：「外部からインポート」「既存の CSV」；右侧为类 Finder 的文件列表
     （名前・日時・長さ・行数・種類・帯域・平均A・平均V・推定），可滚动，单击选中，双击再生。
   - 导入（CsvImport.pde）：选择 Mind Monitor 的 CSV（也接受本系统的 25 列 CSV）→ 按列名读取 5 频段×4 电极 →
     逐行噪声处理（NaN/范围外/接触不良(HSI)/未佩戴(HeadBandOn=0)/咬牙标记）→ 1 秒分箱平均 + 冻结判定 →
     与实时相同的公式计算 A/V → 以 calibration.json 为基准正规化（未校准时以该文件自身为基准）→
     保存为 eeg_session_<录制开始时刻>_mm.csv（25 列）→ 加入列表与画廊日历，并自动回放。
   - 已导入过的同一录制会提示「既にインポートされています」，不会重复保存。
   - 处理在后台线程进行，进度显示在左侧栏。

4. 其他
   - 画廊：悬停信息增加「クリックで再生」；导入的记录显示「Mind Monitor から取り込み」。
   - 菜单：增加 Data Management；回放窗口打开时菜单不会展开。

■ 2026-11-09　EEG 连接判定・录制按钮・画廊删除・频段列
（修改前的版本 → _backup_1109；详细内容见 _backup_1112/更新说明.txt）
